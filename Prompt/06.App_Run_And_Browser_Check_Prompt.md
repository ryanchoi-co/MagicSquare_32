# App Run and Browser Check Prompt

아래 지시를 그대로 수행하라. **현재 개선된 앱**을 실행하고 브라우저(또는 동등한 UI)에서 확인한다.

## 작업

1. 프로젝트 실행 방법을 먼저 확인한다.
2. `package.json`, `README`, 실행 스크립트(`scripts`, `Makefile`, `docker-compose` 등)를 확인한다.
3. 필요한 경우 의존성 설치 여부를 확인한다.
4. 개발 서버를 실행한다.
5. 브라우저에서 주요 화면을 확인한다.
6. 오류가 발생하면 원인과 해결 방법을 보고한다.

## 사전 확인 체크리스트

| 확인 항목 | 위치 예시 |
|-----------|-----------|
| 실행 명령 | `README.md`, `package.json` → `scripts`, `pyproject.toml`, `Makefile` |
| 포트·URL | README, `.env.example`, 프레임워크 기본값(Vite 5173, Next 3000 등) |
| 의존성 | `package-lock.json` / `pnpm-lock.yaml` / `requirements.txt` / `pyproject.toml` |
| 환경 변수 | `.env.example` (값은 출력하지 않음) |

### 웹 UI가 없는 저장소 (예: Magic_Square_XX)

- `package.json`이 없거나 브라우저 앱이 없으면 **개발 서버 실행을 생략**하지 말고, 대체 확인을 명시한다.
- Python/TDD 프로젝트: `pip install -e ".[dev]"` 후 `pytest`로 계약·통합 테스트 실행
- CLI만 있는 경우: README 또는 `pyproject.toml`의 entry point / 모듈 실행 명령으로 주요 흐름 확인
- 브라우저 확인 항목은 `해당 없음 (CLI/테스트만)` 으로 보고하고, **수동 확인 절차**를 출력에 포함한다.

## 브라우저에서 확인할 주요 흐름 (웹 앱인 경우)

- 앱 최초 로드(빈 화면·콘솔 오류 없음)
- 핵심 CRUD 또는 메인 사용자 시나리오 1회 이상
- 폼 입력·제출·성공/실패 피드백
- 에러 상태(잘못된 입력, 네트워크 실패 시 메시지)
- 새로고침 후 상태 유지 여부(해당 시)

## 금지

- 사용자의 승인 없이 패키지 버전 대규모 변경 금지
- 임의로 프레임워크 교체 금지
- 배포 금지
- API Key 또는 환경변수 **값** 출력 금지

## 공통 안전 규칙

- 작업 전 현재 파일 구조와 관련 파일을 먼저 확인한다.
- 변경 전 어떤 파일을 수정할지 먼저 요약한다. (이 프롬프트는 **실행·확인** 위주이며, 수정은 오류 해결에 필요할 때만 최소 범위로)
- 사용자의 명시적 승인 없이 파일 삭제, 대량 이동, Git push, 배포, DB 변경을 하지 않는다.
- 변경 후에는 수정 파일 목록, 변경 이유, 실행한 테스트 명령, 결과를 보고한다.
- 추측으로 수정하지 말고, 근거가 부족하면 `확인 필요`라고 표시한다.
- 보안 정보, API Key, 토큰, 비밀번호를 출력하거나 커밋하지 않는다.

## 출력 형식

# 실행 명령
# 접속 URL
# 확인한 화면
# 발견한 오류
# 해결 여부

### 출력 예시 (웹 앱)

```markdown
# 실행 명령
npm install && npm run dev

# 접속 URL
http://localhost:5173

# 확인한 화면
- 홈: 로드 정상
- 냉장고 목록: 표시 정상
- 항목 추가: 제출 후 목록 반영

# 발견한 오류
- 없음

# 해결 여부
- 해당 없음
```

### 출력 예시 (브라우저 없음 — Magic_Square_XX 등)

```markdown
# 실행 명령
pip install -e ".[dev]"
pytest

# 접속 URL
해당 없음 (브라우저 UI 없음)

# 확인한 화면
- pytest: entity/boundary/integration 계약 통과 여부

# 발견한 오류
- (실패 시 테스트 ID·메시지)

# 해결 여부
- (수정했으면 요약 / 미해결이면 확인 필요)
```

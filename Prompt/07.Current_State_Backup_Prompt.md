# Current State Backup Prompt

아래 지시를 그대로 수행하라. **현재 프로젝트 상태를 백업**한다.

## 작업

1. 현재 Git 상태를 확인한다.
2. 수정된 파일 목록을 확인한다.
3. 백업 방법을 제안한다.
4. 사용자가 승인하면 백업 브랜치 또는 백업 커밋을 만든다.
5. 백업 후 복구 방법을 함께 기록한다.

## 권장 백업 방식

| 조건 | 방식 |
|------|------|
| Git 저장소가 있음 | `backup/YYYYMMDD-HHMM` 브랜치 생성 (필요 시 스냅샷 커밋 포함) |
| Git 없음 | 프로젝트 **루트 밖**에 타임스탬프 압축 폴더 또는 zip 생성 |

### Git 백업 절차 (승인 후)

```text
# 1) 상태 확인
git status
git diff --stat

# 2) 백업 브랜치 (현재 HEAD 기준, 변경 미포함)
git branch backup/YYYYMMDD-HHMM

# 3) 미커밋 변경까지 포함하려면 (사용자 승인 필수)
git add -A   # 또는 사용자가 지정한 경로만
git commit -m "backup: snapshot YYYYMMDD-HHMM"
git branch backup/YYYYMMDD-HHMM
```

- 브랜치만 만들면 **이미 커밋된 상태**만 보존된다.
- **작업 중 변경**까지 보존하려면 커밋 또는 stash를 제안하고, 사용자 승인 후 진행한다.

### Git 없을 때 (승인 후)

- 대상: 프로젝트 루트 전체 (`.git` 제외 여부는 사용자에게 확인)
- 위치 예: `../Magic_Square_XX-backup-YYYYMMDD-HHMM/` 또는 `.zip`
- Windows 예: `Compress-Archive` / `tar -czf` (환경에 맞게 선택)

## 중요

- 사용자의 승인 없이 **Git push**를 하지 않는다.
- 사용자의 승인 없이 **파일을 삭제**하지 않는다.
- 백업 전 **변경 파일 목록**을 반드시 보여준다.

## 공통 안전 규칙

- 작업 전 현재 파일 구조와 관련 파일을 먼저 확인한다.
- 변경 전 어떤 파일·브랜치·커밋을 만들지 먼저 요약한다.
- 사용자의 명시적 승인 없이 파일 삭제, 대량 이동, Git push, 배포, DB 변경을 하지 않는다.
- 백업 후에는 백업 이름, 대상, 실행한 명령, 결과를 보고한다.
- 추측으로 진행하지 말고, 근거가 부족하면 `확인 필요`라고 표시한다.
- 보안 정보, API Key, 토큰, 비밀번호를 출력하거나 커밋하지 않는다.

## 출력 형식

# 현재 Git 상태
# 백업 방식
# 백업 이름
# 백업 대상
# 복구 방법

### 복구 방법 기록 예시 (Git)

```markdown
# 복구 방법
- 백업 브랜치로 이동: `git checkout backup/YYYYMMDD-HHMM`
- 현재 브랜치에 백업 내용만 가져오기: `git merge backup/YYYYMMDD-HHMM` (충돌 가능 — 복구 프롬프트 참고)
- 특정 파일만: `git checkout backup/YYYYMMDD-HHMM -- path/to/file`
```

### 복구 방법 기록 예시 (압축)

```markdown
# 복구 방법
- 현재 폴더를 다른 이름으로 이동한 뒤, 백업 zip을 프로젝트 루트에 풀기
- 또는 diff 도구로 백업 폴더와 현재 트리 비교 후 필요한 파일만 복사
```

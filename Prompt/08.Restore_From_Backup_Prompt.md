# Restore From Backup Prompt

아래 지시를 그대로 수행하라. **이전 백업 상태로 복구**한다.

## 작업

1. 사용 가능한 백업 목록을 확인한다.
2. 현재 작업 상태와 충돌 가능성을 확인한다.
3. 어떤 백업으로 복구할지 사용자에게 확인한다.
4. 승인 후 복구를 수행한다.
5. 복구 후 파일 상태와 실행 가능 여부를 확인한다.

## 백업 목록 확인

### Git

```text
git branch -a | findstr backup
# 또는
git branch --list "backup/*"
git log --oneline -5 backup/YYYYMMDD-HHMM
```

### 압축 / 폴더 백업

- 프로젝트 루트 **상위** 또는 문서화된 백업 경로에서 `*backup*` / `*.zip` 목록
- 수정 시각·크기·포함 경로 요약

## 충돌·위험 점검

| 상황 | 위험 | 사용자에게 알릴 내용 |
|------|------|----------------------|
| 미커밋 변경 있음 | `checkout` / `reset` 시 손실 | stash 또는 새 백업 후 진행 제안 |
| `git clean` 필요 | untracked 삭제 | **반드시** 경고, 승인 없이 실행 금지 |
| `git reset --hard` | 작업 트리 전부 되돌림 | 대상 커밋·브랜치 명시 후 승인 |
| merge 복구 | 충돌 파일 발생 | 충돌 해결 책임·범위 확인 |

## 복구 방식 (승인 후, 목적에 맞게 하나 선택)

| 목적 | 명령 (실행 전 설명·승인) |
|------|---------------------------|
| 백업 브랜치로 완전 전환 | `git checkout backup/YYYYMMDD-HHMM` |
| 현재 브랜치에 백업 반영 | `git merge backup/YYYYMMDD-HHMM` |
| 특정 파일만 | `git checkout backup/YYYYMMDD-HHMM -- <path>` |
| 압축 백업 | 백업 폴더에서 파일 복사 또는 전체 교체(현재 트리 보존 여부 확인) |

## 복구 후 확인

- `git status`, `git diff --stat` (Git인 경우)
- README / `package.json` / `pyproject.toml` 기준 **실행·테스트** 명령 제안 및 실행
  - Magic_Square_XX: `pip install -e ".[dev]"` && `pytest`
  - 웹 앱: `Prompt/06.App_Run_And_Browser_Check_Prompt.md` 참고

## 중요

- 사용자 승인 없이 **복구하지 않는다**.
- 현재 변경 사항이 사라질 수 있으면 **반드시 경고**한다.
- `git reset`, `checkout`, `clean` 같은 명령은 실행 전 **반드시 설명하고 승인**받는다.
- 복구 후 **변경된 파일 목록**을 보고한다.

## 공통 안전 규칙

- 작업 전 현재 파일 구조와 관련 파일을 먼저 확인한다.
- 복구 전 대상 백업·명령·손실 가능성을 요약한다.
- 사용자의 명시적 승인 없이 파일 삭제, 대량 이동, Git push, 배포, DB 변경을 하지 않는다.
- 복구 후에는 실행한 명령, 결과, 테스트 여부를 보고한다.
- 추측으로 진행하지 말고, 근거가 부족하면 `확인 필요`라고 표시한다.
- 보안 정보, API Key, 토큰, 비밀번호를 출력하거나 커밋하지 않는다.

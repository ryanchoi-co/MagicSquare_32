## 문서 목적

본 보고서는 4×4 Magic Square **TDD 연습**을 위해 Dual-Track(UI Boundary + Domain Logic) 및 Clean Architecture 관점에서 레이어·계약·테스트·통합 경로를 고정한다. 알고리즘 난이도보다 **레이어 분리 · 계약 기반 테스트 · 리팩토링** 훈련이 목적이다.

**마방진 정의(고정):** 4×4, 완성 시 값 1~16 각 1회, 마법 상수 **M=34**, 검사 라인 = **행 4 + 열 4 + 주대각 2**(총 10라인, Report 01의 C3·C4와 동일).

**본 과제 범위:** 부분 격자(빈칸 2개)에서 누락 숫자 2개를 찾아 배치하고 `int[6]`으로 반환.

## 고정 입출력 계약 (외부)

### 입력

| 항목 | 규칙 |
|------|------|
| 형식 | `4×4 int[][]` |
| 빈칸 | `0`, **정확히 2개** |
| 값 범위 | `0` 또는 `1~16` |
| 중복 | `0` 제외 중복 **금지** |

### 출력

| 항목 | 규칙 |
|------|------|
| 형식 | `int[6]` = `[r1,c1,n1,r2,c2,n2]` |
| 좌표 | **1-index** |
| n1, n2 | 두 누락 숫자 |
| 순서 | (n_small→첫 빈칸, n_large→둘째 빈칸)이 마방진이면 그 순서; 아니면 반대 배치 순서로 출력 |

### 빈칸 순서 정의

```
스캔: (1,1)→(1,2)→…→(1,4)→(2,1)→…→(4,4)
첫 빈칸  = 첫 번째 value==0
둘째 빈칸 = 두 번째 value==0
```

### 배치 시도

| 시도 | 빈칸1 | 빈칸2 | 성공 시 출력 |
|------|-------|-------|--------------|
| A | n_small | n_large | `[r1,c1,n_small,r2,c2,n_large]` |
| B | n_large | n_small | `[r1,c1,n_large,r2,c2,n_small]` |

A를 먼저 검사; A 실패·B 성공 시 B 출력; 둘 다 실패 시 `NO_VALID_COMPLETION`.

# 1) Logic Layer (Domain Layer) 설계

## 1.1 도메인 개념

| 유형 | 이름 | 책임 (SRP) | 비고 |
|------|------|------------|------|
| Entity | `Grid4x4` | 4×4 셀 집합, 불변 크기 | 완성/부분 격자 공통 |
| Value Object | `CellCoordinate` | 1-index (row,col), 1≤row,col≤4 | 출력 계약과 동일 |
| Value Object | `CellValue` | 0 또는 1~16 | 0 = 빈칸만 |
| Value Object | `MagicConstant` | M=34 | 변경 시 전 테스트 Red |
| Value Object | `LineId` | ROW_i / COL_j / DIAG_MAIN / DIAG_ANTI | 10라인 고정 |
| Value Object | `SolutionVector` | 길이 6, 검증·동등 비교 | UI 출력 1:1 |
| Domain Service | `EmptyCellScanner` | 행 우선 스캔으로 빈칸 2개·순서 | 첫/둘째 빈칸 단일 출처 |
| Domain Service | `MissingValueFinder` | {1..16}\present → n_small≤n_large | |
| Domain Service | `MagicSquareJudge` | 완성 격자 C2·C3·C5 판정 | 합·집합만 |
| Domain Service | `PartialGridSolver` | 두 배치 시도 → SolutionVector 또는 실패 | |

**경계:** Domain은 `int[][]` 원시 배열 미처리; `Grid4x4` 변환 후만 처리.

## 1.2 도메인 불변조건(Invariants)

| ID | 불변 | 완성 격자 | 부분 격자(2빈칸) |
|----|------|-----------|------------------|
| D-C1 | 크기 4×4 | rows=4, cols=4 | 동일 |
| D-C2 | 값 집합 | {1..16} 각 1회, 0 없음 | 비0⊂{1..16}, 0은 2칸 |
| D-C3 | 라인 합 | 10라인 각 =34 | 완성 후 검사 |
| D-C4 | 라인 집합 | 행4+열4+주대각2 | 고정 |
| D-C5 | 총합 | Σ=136 | 완성 시 |
| D-V1 | 결정성 | 동일 입력→동일 출력/실패 | 스캔 순서 고정 |
| D-V2 | 배치 규칙 | n1,n2는 누락 2수; 좌표는 스캔 순 빈칸1·2 | UC-D4 |
| D-V3 | 해 존재 | 두 배치 모두 실패 시 단일 실패 | |

## 1.3 핵심 유스케이스(도메인 관점)

| UC ID | 이름 | 전제 | 성공 | 실패 |
|-------|------|------|------|------|
| UC-D1 | 빈칸 찾기 | D-C1, 0이 2개 | coord1, coord2 (1-index) | `D_ERR_EMPTY_COUNT` |
| UC-D2 | 누락 숫자 찾기 | 비0 중복 없음 | (n_small, n_large) | `D_ERR_DUPLICATE_VALUE`, `D_ERR_VALUE_RANGE` |
| UC-D3 | 마방진 판정 | 0 없음 | boolean | `D_ERR_HAS_EMPTY` |
| UC-D4 | 두 조합 시도 | UC-D1,D2 | SolutionVector | `NO_VALID_COMPLETION` |

## 1.4 Domain API(내부 계약)

| API | 입력 | 출력(성공) | 실패 |
|-----|------|------------|------|
| `Grid4x4.fromRaw(int[][] raw)` | 4×4 | Grid4x4 | `D_ERR_NOT_4X4` |
| `EmptyCellScanner.locate(Grid4x4 g)` | 부분 격자 | (CellCoordinate, CellCoordinate) | `D_ERR_EMPTY_COUNT` |
| `MissingValueFinder.findPair(Grid4x4 g)` | 부분 격자 | (nSmall, nLarge) | `D_ERR_DUPLICATE_VALUE`, `D_ERR_VALUE_RANGE` |
| `MagicSquareJudge.isCompleteMagic(Grid4x4 g)` | 0 없음 | boolean | `D_ERR_HAS_EMPTY` |
| `PartialGridSolver.solve(Grid4x4 g)` | UC-D1,D2 | SolutionVector | `NO_VALID_COMPLETION` |

**SolutionVector 생성 검증:** length=6; 1≤r1,c1,r2,c2≤4; {n1,n2}=missing pair; 좌표 상이; 완성 후 Judge=true.

# 2) Screen Layer (UI Layer) 설계 (Boundary Layer)

## 2.1 사용자/호출자 관점 시나리오

| Step | 동작 | 레이어 |

## 2.2 UI 계약(외부 계약)

### Input schema

| 제약 | 위반 코드 |
|------|-----------|
| 4×4 존재 | `UI_ERR_NOT_4X4` |
| 0 또는 1~16 | `UI_ERR_VALUE_RANGE` |
| count(0)=2 | `UI_ERR_EMPTY_COUNT` |
| 비0 유일 | `UI_ERR_DUPLICATE` |

### Output schema (성공)

`int[6]` = `[r1,c1,n1,r2,c2,n2]`, Domain SolutionVector와 동일.

### Error schema

| code | message (고정) |
|------|----------------|
| UI_ERR_NOT_4X4 | `ERROR: grid must be 4x4` |
| UI_ERR_VALUE_RANGE | `ERROR: cell value must be 0 or 1-16` |
| UI_ERR_EMPTY_COUNT | `ERROR: exactly 2 empty cells required` |
| UI_ERR_DUPLICATE | `ERROR: duplicate non-zero value` |
| UI_ERR_NO_SOLUTION | `ERROR: no valid magic square completion` |
| UI_ERR_INTERNAL | `ERROR: unexpected failure` |

메시지는 **완전 일치** 검증.

# 3) Data Layer 설계

## 3.1 목적

입력 격자·(선택) 실행 결과의 **재현·회귀 픽스처 보관**. Domain은 Repository 미참조.

## 3.2 인터페이스 계약

| 메서드 | 실패 |
|--------|------|
| `save(id, grid, resultOptional)` | `DATA_ERR_INVALID_ID`, `DATA_ERR_INVALID_GRID` |
| `load(id)` | `DATA_ERR_NOT_FOUND`, `DATA_ERR_CORRUPT` |

- id: `^[a-zA-Z0-9_-]{1,32}$`
- LoadedRecord: grid 4×4 UI 계약 동일; resultOptional 있으면 length=6

| **추천** | **1차 Default** | 2차 동일 인터페이스 |

## 문서 목적

본 문서는 Cursor Rules 운영 방식을 단일 `.cursorrules` 중심에서 `.cursor/rules/`의 주제별 `.mdc` 파일 구조로 전환한 내용을 기록한다.  
목표는 규칙의 가독성, 적용 범위(globs) 제어, 유지보수성을 높이는 것이다.

---

## 1) 요청 배경

- 사용자는 이미지 예시와 같은 Cursor Rules 구조(`.cursor/rules/*.mdc`) 구성을 원함.
- 기존 저장소에는 대형 단일 파일 `.cursorrules`가 존재.
- 규칙 중복/충돌을 줄이기 위해 규칙을 역할별로 분리하고, 루트 파일은 안내용으로 축소.

---

## 2) 적용 결과

다음 파일이 생성되었다.

| 경로 | 적용 방식 | 역할 |
|------|-----------|------|
| `.cursor/rules/magicsquare-project.mdc` | `alwaysApply: true` | 프로젝트 개요, SSOT, 문제 범위, 워크플로 |
| `.cursor/rules/magicsquare-ecb-architecture.mdc` | `globs: src/**/*.py` | ECB 레이어 정의, 의존 방향, 포트 규칙 |
| `.cursor/rules/magicsquare-python-code-style.mdc` | `globs: **/*.py` | Python 스타일, 타입힌트, docstring 규칙 |
| `.cursor/rules/magicsquare-tdd-testing.mdc` | `globs: tests/**/*.py` | Dual-Track TDD, pytest AAA, fixture 규칙 |
| `.cursor/rules/magicsquare-forbidden.mdc` | `alwaysApply: true` | 금지 패턴 및 대체 방식 |

루트 `.cursorrules`는 아래 목적의 간단 안내로 정리되었다.

- active rule 파일 목록 안내
- 중복 적용 방지 목적의 마이그레이션 메모

---

## 3) 설계 의도

### 3.1 Always Apply 최소화

- `project`, `forbidden`만 항상 적용하여 토큰 사용량과 규칙 과밀을 완화.

### 3.2 Globs 기반 자동 부착

- 코드 파일(`src/**/*.py`) 작업 시 아키텍처 규칙 자동 부착.
- 테스트 파일(`tests/**/*.py`) 작업 시 TDD/테스트 규칙 자동 부착.

### 3.3 단일 관심사 원칙

- 파일당 한 주제로 분리하여 수정 시 영향 범위를 축소.
- 추후 규칙 추가 시 기존 파일의 대규모 병합 충돌 위험 감소.

---

## 4) 운영 가이드

1. 규칙 수정 시 먼저 해당 주제 `.mdc` 파일만 편집한다.
2. 신규 규칙은 가능하면 기존 파일에 과적재하지 말고 독립 `.mdc`로 추가한다.
3. `alwaysApply: true`는 최소한으로 유지한다.
4. 규칙 내용은 SSOT(`Report/01`, `Report/02`) 기준으로 동기화한다.

---

## 5) 검토 포인트

- Cursor Settings의 Project Rules 화면에서 5개 `.mdc` 인식 여부 확인.
- `tests/entity/*.py` 편집 시 `tdd-testing` 규칙 자동 부착 확인.
- `src/**/*.py` 편집 시 `ecb-architecture` 규칙 자동 부착 확인.
- `.cursorrules`와 `.mdc` 간 중복 정책 문구가 다시 생기지 않도록 주기 점검.

---

## 6) 결론

이번 전환으로 Magic_Square_XX의 Cursor Rules는 이미지 예시와 동일한 멀티 파일 구조를 갖추었다.  
향후에는 SSOT 변경 시 해당 주제 `.mdc`만 업데이트하면 되므로 운영 비용이 낮아지고 규칙 품질을 안정적으로 유지할 수 있다.
